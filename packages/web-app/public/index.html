What it actually did

the record

One Vouch per action: bought, held or disputed. Each shows the chain from your mandate to the checkout, the order and the doorstep.

loading…
About the doorstep: Ring publishes no “package delivered” event. corroborated means a motion event fell inside the window the order was expected in — correlation, never proof. unconfirmed means no such event yet. not applicable means nothing was bought. In this console the doorbell is simulated and nothing scripts it, so a new order reads unconfirmed.

Why not just Auto Buy?

a simulated household, not yours — a year, replayed both ways

Auto Buy orders when the price reaches your target. It never sees how much is left. Vouch's household agent orders when the forecast says you're about to run out. Same household, same year, same habits — only the rule for when to buy differs.

What's real here, and what's simulated

real
  • The MCP server and its gate — it runs before the order, not after
  • The UCP checkout lifecycle (open standard), implemented on both sides
  • The record, the dispute and the threshold change, stored in SQLite
  • The agent: a Strands agent calling the same tools this page calls
simulated
  • The merchant's catalog, and payment — no money moves
  • The doorbell in this console (a real webhook receiver exists, off by default)
  • The written explanations and threshold rules — deterministic, not a model yet
  • Alexa+ itself — this chat stands in for it
